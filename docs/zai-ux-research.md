## 1. Страницы (what routes exist)

| URL | Что это |
|---|---|
| `/` | Лендинг-чат: hero-вопрос + композер по центру + чипсы сценариев + галерея примеров |
| `/auth` | Welcome-экран входа (Google / Email / Github / Skip) + обработчик OAuth-колбэка |
| `/oauth/google/login?t=2` | Серверный запуск Google OAuth (302 на accounts.google.com) |
| `/oauth/google/callback` | Приём `?code=` от Google (redirect_uri жёстко закреплён за ними) |
| `/auth#token=…&is_new_user=…` | Точка приземления после любого соц-логина; токен пишется в `localStorage.token` |
| `/legal-agreement/terms-of-service`, `/privacy-policy` | Юридические страницы |
| `/admin/*` (`/admin/clients`, `/admin/oauth`, `/admin/gallery`, …) | Их внутренняя админка (в т.ч. управление OAuth-клиентами) |
| `/oauth`, `/oauth/test` | OAuth-страницы фронтенда (тестовый роут есть, публичных клиентов не найдено) |

Платформа: **Open WebUI** (форк/наследник — футер честно пишет «Powered by Open WebUI»),
обвязка собственная: CDN `z-cdn.chatglm.cn`, версия фронтенда `prod-fe-1.1.98`,
FE-Version заголовок API `prod-fe-1.0.272`.

## 2. Лендинг (`/`) — эталон «0 лишних кликов»

Композиция (1440×900):

- шапка: логотип Z слева, рядом селектор модели `GLM-5.3-Flash ▾`;
  справа ссылки `ZCode↗`, `API↗` и тёмная кнопка `Sign in`
- слева slim-rail иконок (~56px): новый чат, стикеры, `+`, приложения; внизу — аватар/вход
- центр: крупный serif-заголовок «What can I build for you?» + подзаголовок
- под ним композер: placeholder «How can I help you today?», слева `[+ вложение] [🌐 поиск]`,
  справа `[Deep Think Max ▾]` и круглая кнопка отправки
- ниже ряд чипсов: Landing Page / Knowledge-Teaching Material / 3D Modeling / Mini Game / Personal Blog
- ещё ниже галерея из трёх карточек готовых работ + сноска «Generated by AI…»

Ключевые приёмы, которые дают «ноль кликов»:

1. **Композер — сразу герой страницы**: нет промежуточного лендинга → ввёл текст → чат начался.
2. **Один клик = один сценарий**: чипсы сразу переключают промпт-контекст, без настроек.
3. **Модель видна и переключается из шапки** (не из настроек).
4. **Уровень размышлений — в композере**: `Deep Think Max ▾` → `High / Max / Deep Think`
   (Deep Think гостям disabled — мягкий апселл в Sign in).
5. **Глобус = веб-поиск** одним тапом (по умолчанию выключен).
6. **`+` = вложение файлов** (агент сам читает файлы).
7. **Галерея готовых работ** — мгновенная демонстрация возможностей.
8. **Промоуты в местах блокировок**: залоченные модели и Deep Think открывают
   мини-плашку «Try advanced features — Sign in» прямо в дропдауне.

## 4. Welcome-экран (`/auth`)

Карточка по центру: логотип Z → **«Welcome to Z.ai»** → «Unlock all features by logging in»
→ тёмная кнопка **Continue with Google** → «or» → `Continue with Email` →
`Continue with Github` → `Skip for now` → сноска ToS/Privacy.

Поведение: `Skip for now` кидает на `/`, гости могут чатить сразу (с капчей на
каждом сообщении). Экран принимает URL-параметры (см. §6) — часть их OAuth-механики.

## 5. Google OAuth flow (байт-проверено живьём)

1. Кнопка «Continue with Google» → **серверный** эндпоинт `/oauth/google/login?t=2`
   (клиент Google-URL НЕ строит — state/dsh генерирует сервер, поэтому ссылку
   нельзя захардкодить: `state=state-<hex>` одноразовый и сессионный).
2. Google: `client_id=800424391928-qsq96va3tpufq4aja8a4abiobm910aks.apps.googleusercontent.com`,
   `redirect_uri=https://chat.z.ai/oauth/google/callback` (жёстко),
   `response_type=code`, `scope=openid email profile`, `service=lso`,
   `flowName=GeneralOAuthFlow`/`GeneralOAuthLite`, `dsh=<эфемерный>`.
3. Колбэк → код сервер-сайд обменивается → 302 на `/auth#token=<JWT>&is_new_user=…`.
4. JS `/auth`: читает hash → `localStorage.token = JWT` → трекает
   `sessionStorage.oauth_provider` → далее SSO-обработка.

**Возврат токена третьим доменам — закрыт** (важно для нашего прокси):

- `redirect_uri` у Google прибит к `chat.z.ai` — перехват кода на своём домене
  невозможен (`redirect_uri_mismatch`).
- На `/auth` есть механизм `sso_redirect` (после логина делает
  `location.href = <sso_redirect>?token=<JWT>`), НО валидатор допускает ТОЛЬКО
  whitelist хостов: **`zread.ai`, `test.cgx.dev`, `z.ai`, `www.chatglm.site`**
  (плюс протоколы `zcode:` и `vscode(s)://aminer.codegeex`; https-only, без порта,
  без IP-литералов). `vebai-six.vercel.app` в список не входит и попасть не может.
- `window.opener.postMessage` — не используется: попап-хендшейка нет.
- Их собственный OAuth-провайдер (`/api/oauth/authorize`) на пред-логин этапе
  принимает ЛЮБОЙ `client_id` (307 → `/auth?<все параметры>`), но после логина
  работает только с зарегистрированными клиентами (их админка `/admin/oauth`
  управляет grant-типами authorization_code / refresh_token / client_credentials,
  consent_required, сроки access/refresh токенов). Саморегистрации нет.

**Наш вывод (реализовано в v6-мосте):** единственный честный путь — попап их
настоящего Google-входа + одноразовый bookmarklet/catch-переход
`/auth/google/catch#token=…`, который забирает JWT серверно с живой валидацией.
Альтернатива — стать их зарегистрированным OAuth-клиентом (не self-serve).

## 6. URL-параметры страницы `/auth` (их мосты, байт-проверено)

| Параметр | Эффект |
|---|---|
| `redirect_uri` + `client_id` + `response_type` + `state` | сохраняются в sessionStorage; после логина фронт зовёт `/api/oauth/authorize?…` |
| `sso_redirect` | после ЛЮБОГО успешного логина → `location.href=<sso_redirect>?token=<JWT>` (только whitelist-домены) |
| `redirect` | цель перехода после `Skip for now` / входа |

## 7. Серверный протокол чата (уже интегрирован у нас, сводка)

- `GET /api/v1/auths/` — без Bearer минтит гостя; с Bearer обновляет сессию
  (тихий даунгрейд до гостя при протухшем реальном токене — мы это детектим).
- `POST /api/v1/chats/new` — создание чата; **агент-режим = `type: 'general_agent'`**
  + флаг `features:[{server:'tool_selector_h', status:'hidden', type:'tool_selector'}]`,
  `enable_thinking:true`, `reasoning_effort:'max'` — агент сам выбирает инструменты
  (веб-поиск, генерация картинок, file-QA, code interpreter) на квоте аккаунта.
- `POST /api/v2/chat/completions?…fingerprint…&signature_timestamp=` — HMAC-SHA256
  X-Signature, X-FE-Version, SSE: `chat:completion` (фазы thinking/tool_call/answer,
  delta/edit_content) + `type:'status'` (активность агента) + `chat:title/tags`.
- **Капча**: гостям Aliyun Captcha 2.0 (SceneId `didk33e0`, виджет с o.alicdn.com)
  на КАЖДЫЙ completions → `FRONTEND_CAPTCHA_REQUIRED`; наш релей виджета работает
  с чужого домена (проверено). Signup/signin тоже капча-гейтед;
  `verify_email`/`finish_signup`/`resend_email` — без капчи.
- Регистрация email: `signup` (капча) → код на почту → `verify_email` →
  `finish_signup` → JWT. (Старый контракт «токен в ответе signup» мёртв —
  это и была причина бага «капча зелёная, а верификация не прошла».)

## 8. Что воспроизводим в Vebai (наша реализация, наш код)

1. **Светлая тема + serif-hero** «Что мне построить для тебя?» — композер по центру
   сразу на первом экране (новый чат = лендинг).
2. **Чипсы сценариев** (видео / обложка / исследование / маскот) — клик = готовый
   промпт в композер.
3. **Селектор модели в шапке** + **уровень размышлений** `High/Max` в композере +
   **глобус веб-поиска** — все три реально шлются в payload (`model`,
   `reasoning_effort`, `web_search`) через наш прокси.
4. **Welcome-карточка входа** в стиле z.ai: тёмная кнопка Google, Email ниже,
   или-разделитель; вся наша капча/регистрация остаётся под капотом email-ветки.
5. **Лёгкие промоуты** вместо жёстких гейтов (Z.ai-аккаунт, квота).
6. Существующие ручки агента (24/7 worker, активность, вкладка задач) сохраняются.
